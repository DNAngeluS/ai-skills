# Adopt mode: opt an existing layer into dna

A long-lived node usually has a layer written in an older convention. Adopting it means making it **discoverable and indexed**, never rewriting its content. Trimming an oversized `status.md`, normalising statuses and splitting epics are decisions about what is current, so they belong to `save-state` with a person present.

## Steps

1. **Baseline:** run the validator (`python3 -I ../../scripts/validate_layer.py <node>`, path relative to the agentize skill) and note the FAIL and WARN counts.
2. **Marker:** if `AGENTS.md` lacks `<!-- dna:layer v1 -->`, add it on the line after the first heading (after any YAML frontmatter; with no heading, as the first line after it). Nothing else in the file changes, even if it is over budget (report that; the user or `save-state` decides what moves out). If `AGENTS.md` is missing, stop and tell the user: this is not an adoptable layer.
3. **Index:** if `.memory/` exists without `INDEX.md`, create one: a `<!-- when: ... -->` header and a table `File | Holds | Open when`, one row per `.md` file (the validator requires every `.md` file under `.memory/` to be listed, so cards, decisions and project cards each get their own row); JSON shards and cache directories may be grouped (`inventory/` is one row). Machine shards (`*.json`) are "query with `jq`, never read whole"; cache or dot directories are "do not open; regenerated". If something generates those files, say so in the index and never edit generated files by hand. A generator owns only the files its script or header names; others in the same folder are hand-edited and the index says so. Files outside `.memory/` (for example `.agents/.../index.json`) get no row. Find the generator in: a script under `.agents/`, `scripts/` or the Makefile that names the files, or the JSON headers (`schema`, `tool_version`, `generator`); if it lives outside the node, write "generated by <tool>, not in this node". If the node already has `index.json`, still create `INDEX.md` and list `index.json` as a shard (they differ only by case, so warn that case-insensitive filesystems will collide). An existing `INDEX.md` is never replaced or regenerated, even if it is poor: append missing rows only, and report that it could be richer. Keep a new one short (one line per row, about 4 KB at most): it counts toward the 12 KB session-start set and cannot fix an oversized `status.md`.
4. **Pointer:** if `CLAUDE.md` exists and none of its first five lines mentions `AGENTS.md`, add `Read [AGENTS.md](AGENTS.md) first.` at the top; if absent, create `CLAUDE.md` containing `Read [AGENTS.md](AGENTS.md) first. This file only holds Claude Code specifics.` (no `when:` header; that rule covers `.agents/` and `.memory/` only).
5. **Domain only:** list children that have a layer but no status row (and rows whose child directory is gone) in your report. If `status.md` has no child table, say "no child table" once and summarise instead of listing every child. Symlinked children and `-wt-*` worktrees are reported separately ("not ours" / "worktree") and are not counted as layered children. Do not add cards or rows in adopt mode unless the user asks; do not read inside the children's layers.
6. **Validate again** and report: markers/indexes added, FAIL and WARN before and after, and the three biggest remaining problems with `save-state` as the suggested fix (for example `status.md` over 4 KB, session-start set over 12 KB, epics over budget). Adding an INDEX can push the session-start set over budget and turn a hidden problem into a visible FAIL; say so, and name the real fix (trim `status.md` or move sections out of `AGENTS.md` with `save-state`). Order the biggest problems by size of the overage. Hooks will preload only a capped head of `status.md`, so the node is safe to opt in even while oversized.

## Never in adopt mode

Rewrite, move, trim or rename `status.md`, epics, tasks, handoffs, cards or decisions; touch files a generator owns; write inside a child's layer; commit.
